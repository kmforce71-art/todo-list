# TodoList QA 검증 스킬

이 스킬은 한국어 TodoList 웹앱의 프론트엔드 기능, 접근성(a11y), 반응형 UI, 예외 처리를 검증하는 전문 QA 절차를 제공한다.

## 1. 기능 검증 시나리오
- **할 일 추가**:
  - 일반 텍스트 입력 및 Enter/추가 버튼 클릭 등록
  - 앞뒤 공백 자동 제거(trim)
  - 빈 문자열 및 공백만 있는 입력 시 차단 및 오류 안내 표시
  - 최대 200자 제한 및 초과 입력 방지
  - 한글 IME 조합 중 Enter 시 중복 등록 방지 (`isComposing` 확인)
  - 등록 완료 후 입력 필드 초기화 및 포커스 유지
  - 최신 항목이 목록 최상단에 배치되는지 확인
- **완료 상태 토글**:
  - 체크박스 클릭 또는 레이블 클릭 시 완료 상태 전환
  - 완료 시 텍스트 스타일(취소선, muted 색상) 및 접근성 상태 반영
- **내용 수정**:
  - 수정 버튼 클릭 시 인라인 편집 모드 전환
  - Enter 또는 저장 버튼으로 반영, Esc 키로 취소
  - 빈 문자열로 수정 시도시 에러 안내 및 저장 차단
  - 한글 IME 조합 중 Enter 처리
  - 저장/취소 후 수정 트리거 버튼으로 포커스 복귀
- **개별 삭제 및 실행 취소(Undo)**:
  - 삭제 클릭 시 목록에서 즉시 제거되고 화면 하단에 실행 취소 토스트 노출
  - "실행 취소" 클릭 시 원래 ID, 내용, 완료 상태, 생성일시, 정렬 순서 복원
  - 빠른 연속 삭제 시 최신 1건에 대해 명확한 실행 취소 지원
- **필터 및 검색**:
  - 필터: 전체 / 진행 중 / 완료 버튼 클릭 및 ARIA pressed 속성 확인
  - 검색: 키워드 입력 시 대소문자 무관 부분일치 검색
  - 필터와 검색 조건의 교집합(AND) 적용 검증
  - 검색어 초기화 버튼 동작 검증
  - '검색 결과 없음'과 '전체 목록 비어 있음' 상태 구분 검증
- **완료 항목 일괄 삭제**:
  - 완료 항목이 없을 때 버튼 비활성화(`disabled`)
  - 완료 항목이 있을 때 클릭 시 확인 대화상자(모달) 오픈
  - 대상 개수 표시 일치 여부 확인
  - 취소 시 삭제 취소 및 원래 데이터 보존
  - 확인 시 전체 완료 항목 일괄 삭제 및 포커스 안전 이동

## 2. 접근성(A11y) 검증
- 모든 인터랙티브 요소는 키보드 Tab 및 Enter/Space로 조작 가능해야 함
- 대화상자(모달) 오픈 시 포커스 트랩(Focus Trap), Esc 키 닫기, 닫힌 후 호출 버튼으로 포커스 복귀
- 버튼 레이블에 "수정", "삭제" 외 대상 할 일 텍스트를 포함(`aria-label="<할일제목> 수정"`)
- 색상 외에도 텍스트 및 시각적 기호로 상태 구분
- 텍스트 대비 최소 4.5:1 이상 준수

## 3. 로컬 스토리지 및 복원력 검증
- 데이터 저장 스키마 버전(`schemaVersion: 1`) 포함 여부
- 새로고침 시 데이터 유지
- `localStorage` 손상된 JSON 또는 잘못된 스키마 진입 시 기존 데이터 파괴 방지 및 안내 표시
- `localStorage` 쓰기 실패(QuotaExceeded 또는 차단) 시 앱 지속 사용 가능 및 알림 표시
